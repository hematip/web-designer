# نخودچی — MVP خصوصی

کالری‌شمار فارسی (PWA قابل نصب روی آیفون و اندروید) به‌همراه یک سرور کوچک برای حساب‌ها و همگام‌سازی.
تصمیم‌های محصول، هویت و دامنه: [`../docs/product-ux-brief.md`](../docs/product-ux-brief.md) (بخش ۱۸).

## چه چیزی کار می‌کند

- ثبت‌نام با **کد دعوت** و ورود با نام کاربری و رمز
- onboarding و محاسبهٔ بودجهٔ کالری، پروتئین و ماکروها با قواعد ایمنی (§۹ بریف، با آزمون واحد)
- ثبت غذا: جست‌وجوی فارسی (مقاوم به ي/ك، فاصله و نیم‌فاصله)، **۱۷۸ غذای ایرانی** با واحد خانگی، اخیرها، ثبت سریع کالری، «غذای من»
- ثبت فعالیت (۳۴ فعالیت با MET)، گام، آب، وزن با خط روند، BMI و دور کمر
- گزارش هفتگی و ۳۰ روزه، جدول روزبه‌روز، خروجی CSV
- **آفلاین**: همه‌چیز اول روی دستگاه (IndexedDB) ذخیره و بعد همگام می‌شود؛ چند دستگاه با یک حساب
- نصب روی صفحهٔ گوشی (manifest، آیکن‌ها، service worker، راهنمای نصب داخل اپ)
- تغییر رمز، خروج، حذف کامل حساب

**محدودیت‌ها:** ارزش غذاها و واحدهای خانگی برآورد اولیه‌اند و متخصص تغذیه آن‌ها را بازبینی نکرده است؛ اپ این را با برچسب «تقریبی» نشان می‌دهد. بازیابی رمز فراموش‌شده فقط با دستور ادمین انجام می‌شود (پایین). حالت تیره، بارکد و AI در این نسخه نیستند.

## اجرا روی سیستم خودتان

پیش‌نیاز: Node.js نسخهٔ ۲۲.۱۳ یا بالاتر (از SQLite داخلی Node استفاده می‌شود؛ پایگاه‌دادهٔ جدا لازم نیست).

```bash
npm install
npm test                  # ۳۲ آزمون: محاسبات، داده‌ها، و API روی SQLite و Postgres
npm run build             # ساخت اپ در dist/ به‌همراه sw.js
INVITE_CODE=family npm start   # http://localhost:8787
```

برای توسعه: `INVITE_CODE=family npm run dev:server` در یک ترمینال و `npm run dev` در ترمینال دیگر (http://localhost:5173).

## ذخیره‌سازی

دو حالت دارد و بقیهٔ کد در هر دو یکی است:
- **SQLite:** پیش‌فرض، برای سرور مجازی یا اجرای محلی. یک فایل است و پایگاه‌دادهٔ جدا لازم نیست.
- **Postgres:** وقتی `DATABASE_URL` یا `POSTGRES_URL` تنظیم شده باشد. Vercel به این حالت نیاز دارد، چون فایل‌ها روی آن ماندگار نیستند. با Supabase، Neon یا هر Postgres دیگری کار می‌کند.
  - جدول‌ها در اولین اتصال خودکار ساخته می‌شوند، داخل اسکیمای جدای `nt`.
  - این اسکیما از طریق API عمومی Supabase در دسترس نیست.

آزمون‌های API روی هر دو حالت اجرا می‌شوند. برای Postgres از PGlite استفاده می‌شود.

## تنظیمات (متغیرهای محیطی)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `INVITE_CODE` | خالی | کد دعوت مشترک برای ثبت‌نام. اگر خالی باشد، ثبت‌نام بسته است. |
| `PORT` | `8787` | پورت سرور |
| `DATABASE_URL` | خالی | آدرس Postgres. اگر تنظیم شود، به‌جای SQLite استفاده می‌شود. برای Supabase از آدرس **pooler** (پورت ۶۵۴۳) استفاده کنید. |
| `DB_FILE` | `data/nokhodchi.db` | فایل SQLite وقتی `DATABASE_URL` نیست. **از این فایل بکاپ بگیرید.** |
| `COOKIE_SECURE` | خودکار | پشت HTTPS، کوکی‌ها Secure می‌شوند (از روی `X-Forwarded-Proto`). `1` یعنی همیشه Secure. |

## انتشار روی Vercel

- ریپو به یک پروژهٔ Vercel وصل است. هر push به `main` خودکار منتشر می‌شود.
- تنظیمات در `vercel.json` است:
  - `npm run build`، خروجی `dist/`
  - API به‌صورت Vercel Function در `api/handler.js`، منطقهٔ `fra1`
  - هدرهای امنیتی و کش
- متغیرهای لازم در پروژهٔ Vercel:
  - `DATABASE_URL`، یا `POSTGRES_URL` که اتصال Neon از بخش Storage خودکار می‌سازد
  - `INVITE_CODE`
- بدون پایگاه‌داده، خود اپ باز می‌شود ولی ورود و همگام‌سازی پیام «سرور در دسترس نیست» می‌دهند.

## انتشار روی سرور مجازی (جایگزین)

نصب روی گوشی (به‌ویژه آیفون) و کار آفلاین فقط روی **HTTPS** کار می‌کند. ساده‌ترین راه، یک سرور مجازی کوچک (ترجیحاً داخل ایران، تا در قطعی اینترنت بین‌الملل هم در دسترس بماند) با یک دامنه است:

```bash
# روی سرور
docker build -t nokhodchi .
docker run -d --name nokhodchi --restart unless-stopped \
  -e INVITE_CODE='یک-کد-دلخواه' -v nokhodchi-data:/data -p 127.0.0.1:8787:8787 nokhodchi
```

و یک reverse proxy با HTTPS جلوی آن، مثلاً Caddy (`/etc/caddy/Caddyfile`):

```
nokhodchi.example.ir {
  reverse_proxy 127.0.0.1:8787
}
```

بعد آدرس را برای خانواده بفرستید. آن‌ها:
1. با کد دعوت حساب می‌سازند.
2. اپ را نصب می‌کنند: آیفون از Safari ← «اشتراک‌گذاری» ← «Add to Home Screen»؛ اندروید از Chrome ← منوی ⋮ ← «Install app».
3. یک بار دیگر داخل اپ نصب‌شده وارد می‌شوند. آیفون حافظهٔ اپ نصب‌شده را از Safari جدا نگه می‌دارد.

## دستورهای ادمین

```bash
npm run admin -- users                                   # فهرست کاربران
npm run admin -- reset-password <username> <new-pass>    # رمز فراموش‌شده
npm run admin -- delete-user <username>
```
داخل Docker: `docker exec -it nokhodchi node server/admin.js users`. برای Postgres، همین دستورها را با `DATABASE_URL` تنظیم‌شده اجرا کنید.

## آزمون دستی سرتاسری

با سرور در حال اجرا (`INVITE_CODE=family`):
```bash
OUT=shots node scripts/smoke.mjs
```
این اسکریپت در Chromium با اندازهٔ گوشی این مسیر را اجرا می‌کند و از هر صفحه اسکرین‌شات می‌گیرد: ثبت‌نام، onboarding، ثبت غذا و فعالیت و آب، وزن، گزارش، ثبت آفلاین و همگام‌سازی، و ورود از دستگاه دوم.

## ساختار

```
server/       API (node:http)، ذخیره‌سازی SQLite و Postgres، دستورهای ادمین
api/          ورودی Vercel Function
src/lib/      محاسبات، جست‌وجوی فارسی، تاریخ شمسی، ذخیرهٔ محلی و همگام‌سازی
src/data/     بانک غذا و فعالیت‌ها
src/screens/  صفحه‌ها و شیت‌ها
src/ui/       مسکات، کیت رابط، نمودارها
scripts/      ساخت service worker، ساخت آیکن‌ها، آزمون سرتاسری
tests/        آزمون‌های واحد و API
```

فونت‌ها: Vazirmatn و Lalezar، هر دو با مجوز OFL؛ فایل مجوزشان در `src/assets/fonts/` است. همه‌چیز روی سرور خود اپ سرو می‌شود و هیچ درخواستی به دامنهٔ خارجی نمی‌رود.
